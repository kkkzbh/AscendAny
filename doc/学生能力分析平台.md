- # 学生能力分析平台
    ## 增量输入数据: Ascend/data/practice/
    ### 特点
    - 每一个类型的数据在practice下用目录组织
    - 每个目录内的格式相同
    - 以后可能新增数据，可能是每个目录内的数据，亦或者是新增一个类型的数据(目录)
    - 数据被预处理后会以合理的方式存入数据库被后续使用
    ### 数据库: postgreSQL，通过6432的pgbouncer访问
    - 在~/service/postgresql/README.md 中查看文档
    - 设计合理的数据库表 每一张表 都设计一个sql文件存储下来
    - 预处理数据存储到数据库的代码存放到preprocess/ 中
        - 预处理代码需要考虑，输入数据是增量输入数据，且旧数据是永久保留的
        - 你需要确保重复运行代码不会导致旧数据被重复导入数据库，而只预处理和导入那些增量的数据
    ### 系统执行逻辑
    1. 在practice中增加若干单位的数据，每个可能是一个新的目录，可能是一个旧目录内的一个目录
    2. 根据新增的增量数据，预处理，导入数据库
    3. 更新每个学生的能力指标和rating
    注意: 该处理逻辑的假设前提为**每一个单位的数据都视为一场考试**

    ### 学生五大能力指标(均为0-100分制度)
    概念: 五大指标均最大化的反应当前短期内学生的表现，在时序逻辑处理下太久远的将对指标得分的影响占比比较小。
    1. 知识: 反应学生整体知识的掌握程度
    - 一场考试全部题目的通过率，亦或者得分率可以反应本场考试的掌握程度
    - 引入时序处理逻辑，学生最近的单场考试对知识能力的影响更大，越久远的影响越少
    2. 准确
    - 反应学生每场考试中，对于一道题目AC时累计的提交次数
    - 惩罚那些对题目WA太多次的人
    - 同时序处理逻辑
    3. 质量
    - 主要反映代码风格写法，AC时代码的运行时间等反应质量的内容
    - 目前数据中没有提交记录的代码，暂时参考运行时间等已有且可反应质量的数据
    - 同时序逻辑处理
    4. 灵活
    - 反应学生临场应变的能力
    - 该指标的公式需要仔细设计，使得具有以下特点
        - 平推式选手(每个AC的题的提交间隔比较短)的该项得分需要很高
        - 奖励一些某个题有不长的WA提交间隔，开始转到其他题目提交
        - 惩罚那些卡在一个题目上太长时间的人，如若那题最后没有AC则加大惩罚
    - 同时序逻辑处理
    5. 熟练
    - 反映学生的解题速度
    - 做题越快的人该项得分就越高
    - 同时序逻辑处理
    注: 五个指标的公式不应该是写死的一个公式，都要结合单场考试内所有学生的相对表现程度来打分，每场考试都应算出五个指标的得分，然后由时序处理模块来决定如何融合这些算出当前总五大指标得分
    ### 综合能力分数(rating) (不设限制，从0分开始计算)
    - 参考doc/Codeforces_Rating_Formula_Summary.md (codeforces的rating计算公式)
    - 结合当前已有的数据特点设计一套rating计算公式
    - 为每个学生得出一个当前rating值
    - 每场考试都应当能产出一个rating变化数值
    - 初始rating设计为800
    ### Agent对话系统
    - 对话记录客户端本地存储(不需要是用户可读的，只要能加载就可以)
    - 单会话设计,上下文做auto-compact处理，用户可选择清空当前上下文
    - 每日首次登录且最近有新考试数据导入(对AI视角来看)自动触发一次预设prompt的回答，让LLM直接给出近期表现的分析结果
    - 我可能会切换不同的模型的API配置，所以最好把API配置组织到单独的一个目录下，方便热切换，比如切换chatgpt与claude与deepseek三个模型的API，这些均由服务器自行选择加载的配置
    - 目前API只考虑兼容OpenAI和Anthropic两大格式
    - Agent需要拥有Agent skills的能力，最需要有的一个就是访问这个项目的学生数据数据库

    ### 落地实现(平台)
    - 前端 Electron(Vite + React) + 后端 Fast API
    - 以现代化工程的角度组织项目目录
    - 需要严格设计编写tests并通过tests
    - Agent基于一个API来做开发，Agent skills可以通过预先编写如何用CLI访问数据库和prompt工程来解决
    ### UI设计
    - 扁平化/毛玻璃风格
    - 顶部标题栏(在右侧设置一个齿轮按钮(设置), UI图片结构化组织的存放某目录中，你可以有一个占位图片也可以没有，我后续会去补充图标图片)
    - 左侧为对话框+输入框组件
    - 右侧为五大能力指标和rating的显示
    - 左右侧默认比例为6比4，支持拉取，最小占比3，也就是最小37或者73
    - 设置是一个对话框界面，采用常用的侧边栏加右侧页面即可
