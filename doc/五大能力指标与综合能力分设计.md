# 五维能力指标与 Rating：`ascendany_analytics_v1`

本文记录 Go package `backend/internal/analytics` 当前实现的 versioned algorithm contract。运行时配置的 closed shape 位于 `deploy/v2/config/analytics.json.example`；每个 generation 会保存 algorithm version、config SHA-256、完整 snapshot manifest 和 base/head revision。

## 输入

算法只读取已通过 schema、semantic、count、hash 与 reference validation 的 `ascendany.pintia.snapshot.v2` 数据。每个 logical exam 的 active immutable snapshot 提供：

- problems；
- participants 与可选 ranking/result；
- 完整 programming submission 时间线；
- verdict、score、runtime 和 memory 等可选 typed field；
- problem set start/end、total score 和 source timestamp。

缺失的可选测量保持 `NULL`。算法不会解析 legacy 文件、自由文本或未知字段。

## 单场原始指标

令 `P` 为题目数，`A_i` 为学生 `i` 通过的 distinct problem 数，`S_i` 为 submission 数。

### Knowledge

- ranking 提供 `totalScore` 且 problem set 提供正的 `totalScore`：`totalScore_i / totalScore_exam`；
- 其余已验证形状：`A_i / max(1, P)`。

### Accuracy

学生有 submission 时：

`A_i / S_i`

没有 submission 时该指标为 `NULL`。

### Quality

每题先取得每位学生最快 accepted runtime，再计算题内 median。学生在每道有测量的通过题上得到：

`runtimeRatio = fastestAcceptedRuntime / problemMedianRuntime`

学生原始值为：

`1 / median(runtimeRatio)`

没有可比较 accepted runtime 时该指标为 `NULL`。

### Flexibility

submission 按 `(submittedAt, submissionIdentityId)` 严格排序。定义：

- `efficiency = A_i / S_i`；
- `switchRate = 相邻 submission 切换题目的次数 / max(1, S_i - 1)`；
- `coverage = distinctAttemptedProblems / max(1, P)`。

原始值：

`efficiency × (0.5 + 0.5 × switchRate) × (0.5 + 0.5 × coverage)`

没有 submission 时该指标为 `NULL`。

### Proficiency

分子优先使用 ranking total score；未提供 total score 时使用 `A_i`。时长优先使用正的 ranking `timeUsedSeconds`；未提供时使用首尾 submission 的分钟差，最小取 1 分钟。

`score / minutes`

没有确定时长时该指标为 `NULL`。

## 单场相对分

每个指标独立执行：

1. 使用配置的 `winsor.low/high` 计算线性插值 quantile；
2. 将原始值截断到该区间；
3. 对截断值排序，并列项使用 midrank；
4. `score = (lessCount + 0.5 × equalCount) / population × 100`；
5. 结果保留 6 位小数。

只有具备该指标原始值的学生进入对应 population。每项最终范围为 `[0, 100]`。

## 当前画像

对学生的每个指标独立使用 half-life 加权：

`weight = exp(-ln(2) × ageDays / halfLifeDays)`

`current = sum(weight × score) / sum(weight)`

五个 half-life 都是必填配置。reference time 固定为 manifest 中最后一场考试的 deterministic event time。

## Rating

- 初始值来自 `rating.initial`，默认示例为 800；
- 有官方 ranking 时使用官方 rank；
- 没有 ranking 的 participant 按 `score desc, time asc, actorId asc` 生成 competition rank；
- expected rank、几何平均 target rank、performance 二分搜索、第一次总量平移和第二次高分段平移遵循 [Codeforces 得分计算公式](Codeforces得分计算公式.md)；
- `delta` 四舍五入为整数，最终 Rating 下限为 0；
- 每个 history point 保存 rank、old/new rating、delta、seed 和 performance。

## 确定性与发布

- snapshot 先按 `(eventTime, examId, snapshotId)` 排序；
- actor、problem、submission 和结果输出均使用稳定 identity 排序；
- accepted verdict set、winsor、half-life 与 rating bounds 全部进入 canonical config SHA-256；
- analytics publish 重新验证完整 input manifest 与当前 exam heads，并 CAS base analytics head；
- head 已变化的 generation 进入 `superseded`，随后从最新 heads 创建 replacement generation；
- 所有 stored JSON 在读取时重新执行 closed-shape、finite-number、ordering 和 provenance validation。
