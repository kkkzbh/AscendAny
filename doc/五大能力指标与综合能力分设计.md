# 五大能力指标 + rating 设计（每场相对打分 + 时序融合）

## 0. 总原则
1. **每个考试单位都视为一场考试**，需要产出：
   - 本场每个学生的五大指标得分（0-100）
   - 本场 rating 变化量与新 rating
2. **本场得分必须依赖本场相对表现**：同样的原始表现，在强者场/弱者场的 0-100 得分应不同。
3. **学生当前画像要偏向短期**：越近的考试权重越大，久远数据权重衰减（半衰期可配置）。

## 1. 每场的原始特征（features）
下列特征优先从“成绩单 XLSX”抽取；缺失时再用“提交记录 CSV”补足。

### 1.1 知识（Knowledge）
目标：反映本场对知识点的掌握程度。

推荐原始特征：
- `score_rate = total_score / total_points`
- 若是 ICPC：`solve_rate = solved_count / problem_count`

### 1.2 准确（Accuracy）
目标：惩罚 WA 多、靠试错堆出来 AC 的情况。

推荐原始特征：
- `avg_attempts_per_solved`: 解出题目的平均提交次数（从 `score(attempts:ms)` 或 ICPC 的 `+k` 提取）。
- `wa_before_ac_rate`: `(总错误提交数) / max(1, solved_count)`

方向：越小越好（最终得分需要反向映射）。

### 1.3 质量（Quality）
目标：用可得信号近似代码质量（当前以运行时间/内存为主）。

推荐原始特征：
- 对每道 AC 题，取 `runtime_ms`（或提交记录中的耗时）。
- 做题目内归一化：`runtime_ratio = runtime_ms / median_runtime_ms_of_problem`（越小越好）。
- 学生级聚合：`median(runtime_ratio)` 或 `mean(log(runtime_ratio))`。

方向：越小越好（反向映射）。

### 1.4 灵活（Flexibility）
目标：反映临场应变能力，满足：
- 平推式选手（连续 AC 间隔短）得分高。
- WA 后能及时切换到其他题尝试的得分更高。
- 卡死在某一题很久的惩罚；若最终未 AC，加大惩罚。

推荐原始特征（需要提交时间线，优先来自 `提交记录.csv`）：
- `ac_pace`: 相邻两次 AC 的中位时间间隔（越小越好，反向映射后加分）。
- `switch_after_wa_rate`: WA 后下一次提交是否切换题目（在阈值时间内切换记为 1）。
- `max_stuck_minutes`: 在同一题上连续尝试的最长时长（越大越差）。
- `unsolved_stuck_minutes`: 对最终未 AC 的题，卡住时长的聚合惩罚项。

当某类考试无法稳定完成“提交记录 -> 学生”映射时：
- 允许该场 `flexibility` 先用弱替代特征（例如基于 attempts 分布与总耗时的代理特征），并在 `details` 中标注 `flexibility_mode=approx`。

### 1.5 熟练（Proficiency）
目标：解题速度，做题越快得分越高。

推荐原始特征：
- `time_used_seconds`（成绩单提供）
- `score_per_minute = total_score / max(1, time_used_seconds/60)`

方向：越大越好。

## 2. 每场的 0-100 打分（相对）
对每个指标，先得到一个“方向统一”的数值 `v_i`（越大越好）。

推荐相对打分方法（稳定且易解释）：
1. 对 `v_i` 做 winsorize（例如 5%/95% 截尾），降低极端值影响。
2. 计算百分位 `p_i`（含并列的平均名次）。
3. `score_i = round(100 * p_i)`，落在 `[0, 100]`。

注意：
- 缺考：本场五大指标可置为 `NULL`（不参与时序融合），rating 不变。
- 小样本场（n 很小）：可降低分位映射的陡峭度（例如用 z-score + logistic），避免“一题决定一切”。

## 3. 时序融合（当前画像）
对每个学生、每个指标，维护一个“当前值”（0-100）。

推荐半衰期加权平均：
- 对历史每场得分 `s_k`，权重 `w_k = exp(-ln(2) * age_days / half_life_days)`
- 当前值 `S = sum(w_k * s_k) / sum(w_k)`

半衰期建议做成可配置参数（不同指标可不同）：
- Knowledge: 30-60 天
- Accuracy: 15-30 天
- Quality: 30-60 天
- Flexibility: 15-30 天
- Proficiency: 15-30 天

## 4. rating 设计（参考 Codeforces）
rating 目标：
- 不设上限，初始 800。
- 每场考试产出 `delta`（涨跌分），并更新新 rating。

推荐采用 Codeforces rated contest 的核心框架（详见 `doc/Codeforces得分计算公式.md`）：
- 输入：赛前 rating `r_i`、本场名次 `rank_i`（1 最好）
- 计算期望名次（seed）、几何平均名次 `m_i`
- 反求表现分 `R_i`（二分搜索）
- 初始变化：`d_i = (R_i - r_i) / 2`
- 两次整体平移抑制通胀（inc_1, inc_2）
- 输出 `delta_i`

### 4.1 本场排名如何定义
按考试类型选择：
- 分数制（datastructure/pta_ioi）：`total_score` 降序，`time_used_seconds` 升序（若有），再按学号稳定排序。
- ICPC：按 `通过数` 降序，`用时` 升序，再按学号稳定排序。

缺考不参与 rating 计算。
