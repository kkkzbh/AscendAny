# 平台落地架构（Electron + FastAPI + Agent）

## 1. 项目形态（建议目录结构）
为了前后端解耦与可测试性，建议采用 monorepo：
- `apps/desktop/`: Electron (Vite + React)
- `apps/api/`: FastAPI
- `packages/shared/`: 共享协议与类型（例如 OpenAPI schema、前端 DTO、能力指标定义）
- `preprocess/`: 增量导入与计算（可作为独立模块/服务）
- `db/schema/`: Postgres DDL
- `doc/`: 设计文档

## 2. UI 结构要求（强约束）
- 扁平化/毛玻璃风格。
- 顶部标题栏：右侧齿轮按钮（设置）。
- 左侧：对话记录 + 输入框。
- 右侧：五大能力指标 + rating 展示。
- 左右默认比例 6:4，可拖拽，最小占比 3（约 37% 或 73%）。
- 设置界面：对话框形式，左侧栏 + 右侧页面。

## 3. Agent 对话系统（客户端为主）
### 3.1 对话记录存储
- 客户端本地持久化即可（不要求人可读，但要可加载）。
- 单会话设计：只维护一个 active 会话。
- 支持用户清空上下文（同时清除本地存储的会话内容）。

### 3.2 上下文 auto-compact
推荐策略：
- 维护 `messages` + `summary` 两层。
- 当 token 预算超阈值时，将最早的一段对话总结进 `summary`，并保留最近 N 轮原文。

### 3.3 每日首次登录自动分析
触发条件（客户端视角）：
- “今天首次打开应用”
- 且“自上次自动分析以来，DB 中出现了新导入的考试”

实现建议：
- 客户端保存 `last_auto_analysis_at`（本地）。
- API 提供 `GET /meta/latest_exam_imported_at`（或等价）用于判断是否有新考试。
- 触发后用预设 prompt 让 LLM 生成近期表现分析，写入对话记录。

## 4. 模型 API 配置热切换
目标：可能切换 ChatGPT/Claude/DeepSeek 等，服务端按配置加载。

建议组织方式：
- `config/providers/` 下按 provider 放置配置模板（不含密钥）
  - `openai.json`
  - `anthropic.json`
  - `deepseek.json`（若兼容 OpenAI 格式）
- 密钥走环境变量（例如 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`）

兼容范围：
- 当前仅保证兼容 OpenAI 与 Anthropic 两大格式。

## 5. Agent skills（最关键：数据库访问）
建议把 skills 做成可版本化的“说明 + 可执行命令”：
- 例如 `agent/skills/db_student_data.md`
  - 明确如何用 CLI/HTTP 查询学生画像、某场考试详情、rating 轨迹
  - 约定返回格式，便于 prompt 工程复用

## 6. 测试要求（必须）
### 6.1 后端/预处理
- 覆盖：增量导入幂等、编码识别、XLSX/CSV 解析、五大指标得分相对打分、rating 回放一致性。

### 6.2 前端
- 覆盖：分栏拖拽边界、设置对话框、上下文清空、auto-compact 的展示一致性。
