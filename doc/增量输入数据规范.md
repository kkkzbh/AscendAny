# practice 增量数据规范（基于真实样例抽象）

本文档基于当前机器上真实数据样例抽象：
- 数据根目录样例：`/home/kkkzbh/code/Ascend/data/practice`

系统实现时必须支持通过配置指定数据根目录（例如 `PRACTICE_DATA_ROOT`），不要写死本机路径。

## 1. 总体结构
`practice/` 下按“数据类型”分目录组织；每个类型目录下按“考试单位”分子目录（每个子目录视为一次考试）。

通用规则：
- 一个“考试单位目录”内通常包含：
  - `答卷/0-ANSWER.html`（试卷信息与题面/标准答案）
  - `提交记录/*.csv`（逐提交记录）
  - `成绩单/*.xlsx`（按学生汇总的成绩单/榜单）
- 类型目录内可能存在 `tmp/`，应忽略。

当前已观察到的类型目录：
- `datastructure/`
- `pta_icpc/`
- `pta_ioi/`

## 2. datastructure（数据结构月测/月考）
目录样例：
- `datastructure/2025第一次月考/`
  - `答卷/0-ANSWER.html`
  - `提交记录/提交记录all.csv`（也可能是 `提交记录.csv`）
  - `成绩单/*.xlsx`

### 2.1 提交记录 CSV（utf-8，无表头）
文件样例：`datastructure/2025第一次月考/提交记录/提交记录all.csv`

观察到的行格式（逗号分隔，字段尾部常带 `\\t`，末尾存在空字段）：
1. `提交时间`（如 `2025/03/26 11:09:31`）
2. `判题结果`（如 `答案正确`、`答案错误`、`编译错误`、`多种错误`）
3. `得分`（如 `15`、`0`）
4. `题目编号`（如 `6-1-2`、`7-1-3`）
5. `用户标识`（样例中是短昵称，如 `kami`）
6. `语言`（如 `C (gcc)`）
7. `内存/代码体积`（样例形如 `552 KB`，需按实际含义入库，建议统一存 `memory_kb` + 原文）
8. `耗时`（如 `14 ms`）
9. 末尾空字段（忽略）

实现建议：
- 用逗号做分隔，再对每个字段 `strip()`（去掉尾部 `\\t`）。
- 对 `KB/ms` 做数值提取：`552 KB -> 552`，`14 ms -> 14`。

### 2.2 成绩单 XLSX（多个 Sheet）
文件样例：`datastructure/2025第一次月考/成绩单/2025年春学期数据结构月测-01-成绩单-*.xlsx`

观察到的特征：
- 有多个 sheet：`Sheet0..Sheet4`（其中 `Sheet0` 是“全体考生”，其余为分组）。
- 表头包含：
  - `用户组`
  - `学号/邮箱、电话`（可作为主要学生标识）
  - `姓名/昵称`
  - `总分(...)`、`排名`、`耗时(秒)`
  - 每题分值列（例如 `15.0`、`20.0`），以及题号列（例如 `6-1-1`）
- 每题单元格值可能是：
  - `-` 表示未作答
  - `缺考`
  - 形如 `15.0(2:196ms)`：建议解析为 `score=15.0`、`attempts=2`、`runtime_ms=196`

### 2.3 答卷 HTML
文件样例：`datastructure/2025第一次月考/答卷/0-ANSWER.html`

观察到的特征（可用 HTML 解析提取）：
- 标题包含考试名（`<title>...</title>`）
- 页面内包含：
  - `开始时间`、`结束时间`、`答题时长`、`试卷总分`
  - 题目分组（函数题/编程题）、题号、题面（Markdown 渲染后 HTML）

## 3. pta_icpc（ICPC 计分规则的竞赛）
目录样例：
- `pta_icpc/d3/`
  - `答卷/0-ANSWER.html`
  - `提交记录/*.csv`（通常为 `gb18030`）
  - `成绩单/*.xlsx`

### 3.1 提交记录 CSV（常见 gb18030，有表头也可能没有）
文件样例：`pta_icpc/d3/提交记录/xinshengying1.csv`

观察到的行字段（CSV 引号包裹，字段尾部常带 `\\t`）：
1. `提交时间`
2. `判题结果`（如 `答案正确/答案错误/运行超时/...`）
3. `得分或详情`（样例文件该列恒为 `详情`，建议原样入库并尽量解析成数值）
4. `题目编号`（如 `L1-3`、`L2-9`、`7-1`）
5. `学号/账号`（样例为学号：`20230513032`）
6. `姓名`
7. `语言`
8. `内存`（`xxxx KB`）
9. `耗时`（`xx ms`）

编码建议：
- 优先尝试 `utf-8/utf-8-sig`，失败后使用 `gb18030` 解码。

### 3.2 成绩单 XLSX（榜单式）
文件样例：`pta_icpc/d3/成绩单/竞赛1-成绩单-*.xlsx`

观察到的表头：
- `排名`、`学号/邮箱、电话`、`姓名/昵称`、`通过数`、`用时`
- 题目列形如 `7-1..7-10`

每题单元格常见取值（需要解析成结构化信息）：
- `-`：未尝试或未通过（按 PTA 实际定义）
- `-10`：未通过且有 10 次错误提交（错误数）
- `+\\n9`：通过，错误数为 0，通过时间/罚时为 9
- `+1\\n61`：通过，错误数为 1，通过时间/罚时为 61

## 4. pta_ioi（IOI 计分规则/分数制）
目录样例：
- `pta_ioi/d1/`
  - `答卷/0-ANSWER.html`
  - `提交记录/*.csv`（常见 gb18030）
  - `成绩单/*.xlsx`

成绩单结构接近 `datastructure`：
- 有 `总分(...)`、`排名`、`耗时(秒)`，并有每题的 `score(attempts:runtime)` 格式
- 可能出现 `缺考`

## 5. 重要现实问题：身份映射（student identity）
数据源对“学生身份”的表达不完全一致：
- `pta_*` 通常直接提供学号（稳定）。
- `datastructure/提交记录` 观察到的是短昵称（例如 `kami`），而成绩单里是学号+姓名。

落地实现时必须引入“身份映射层”（见 `doc/数据库设计.md` 的 `student_identities` 设计）：
- 同一学生可能有多个外部身份（学号、MOOCID、昵称）。
- 当无法自动映射时，允许先入库为独立身份，后续通过人工/规则合并到同一学生。
