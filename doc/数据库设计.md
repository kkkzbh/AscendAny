# 数据库设计（PostgreSQL）

> 目标：既能支撑增量导入与回放，又能支撑 UI/Agent 查询，同时保留足够的原始细节用于后续调参。

本仓库的 DDL 以“每张表一个 SQL 文件”存放在：
- `db/schema/`

## 1. 核心设计点
- **考试为中心**：`practice/<type>/<exam_dir>` 是最小导入单位。
- **增量 + 幂等**：用唯一约束与 `row_hash` 去重，允许重复运行。
- **身份映射层**：不同数据源对学生的标识不一致，需要 `student_identities` 统一。
- **原始与派生分离**：原始提交/成绩入库后，再写派生指标与 rating 轨迹，便于复算。

## 2. 主要表（概念）
- 学生域
  - `students`: 规范化后的“学生实体”（可被合并）。
  - `student_identities`: 外部身份（学号、昵称、MOOCID 等）到学生实体的映射。
- 考试域
  - `exams`: 考试单位（类型 + 目录路径唯一）。
  - `exam_files`: 本次导入的源文件清单与 hash（支撑快照与追踪）。
  - `exam_problems`: 本场题目与分值信息。
  - `exam_participants`: 本场学生成绩汇总（总分/排名/耗时/通过数等）。
  - `submissions`: 提交记录（逐提交）。
- 指标与 rating
  - `exam_student_metrics`: 本场五大能力指标得分（0-100）与细节。
  - `student_current_metrics`: 时序融合后的学生当前画像（0-100）。
  - `rating_history`: 每场 rating 变化轨迹（含 old/delta/new）。
- 导入追踪
  - `ingest_runs`: 一次导入执行的元信息。
  - `ingest_exam_runs`: 关联到单场考试的导入状态与 fingerprint。

## 3. schema 命名
DDL 使用独立 schema：
- `ascendany`

避免污染 `public`，也便于未来多项目共用一个数据库。

## 4. 如何应用 DDL（示例）
推荐通过 PgBouncer（`6432`）连接，并将密码放在本机 `~/.pgpass`（权限必须为 `600`）。

`~/.pgpass` 示例（不要提交到仓库）：

```text
<host>:6432:<db>:<user>:<password>
```

应用 DDL（`-w` 表示只用 `~/.pgpass`，不进行交互式密码提示）：

```bash
psql -w -h <host> -p 6432 -U <user> -d <db> -f db/schema/000_schema.sql
psql -w -h <host> -p 6432 -U <user> -d <db> -f db/schema/001_students.sql
...
```

建议后续引入迁移工具（如 Alembic），但仍保留“每表一文件”的可读 DDL 作为设计源。
