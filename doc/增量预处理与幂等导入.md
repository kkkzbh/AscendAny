# 增量预处理与幂等导入（实现对齐版）

## 1. 目标
- 从 `practice/` 读取增量考试数据（新目录或新文件）。
- 预处理为结构化数据并写入 PostgreSQL（通过 6432 pgbouncer）。
- 重复运行不会重复导入旧数据；只处理新增“考试单位”或新增“快照”。
- 每个考试单位都视为一次考试：导入后需要更新该场的五大指标与 rating 变化。

## 2. 增量扫描策略
### 2.1 考试单位识别
将以下路径视为考试单位目录（示例）：
- `practice/datastructure/<exam_dir>/`
- `practice/pta_icpc/<exam_dir>/`
- `practice/pta_ioi/<exam_dir>/`

忽略：
- `tmp/`
- 隐藏文件与 Windows 附带的 `:Zone.Identifier`

### 2.2 单位唯一键（source key）
建议使用：
- `exam_type`：顶层类型目录名（如 `datastructure`）
- `source_path`：相对 `practice_root` 的单位路径（如 `datastructure/2025第一次月考`）

数据库对 `(exam_type, source_path)` 做唯一约束，从而确保不会重复创建同一场考试。

### 2.3 快照指纹（fingerprint）
为了支持“同一目录后续补充文件”的情况，建议对单位目录生成 `fingerprint`：
- 收集单位目录下所有关键信息文件：`答卷/*.html`、`提交记录/*.csv`、`成绩单/*.xlsx`
- 对每个文件计算 `sha256`，再对 `(relative_path, sha256)` 列表做稳定排序并汇总 hash

导入时：
- 若该 `fingerprint` 已被记录（`exam_files` 已包含同样的文件集合或 `ingest_exam_runs.fingerprint` 已存在），则跳过。
- 若 `fingerprint` 不同，执行一次“新快照导入”（需要保证行级别幂等）。

## 3. 解析与入库的分层
建议拆分为 5 层：
1. `discover`: 扫描出新增考试单位（或新增快照）。
2. `extract`: 解析 CSV/XLSX/HTML，产出标准化的中间结构（dict/list）。
3. `load`: 写入 DB（优先使用 upsert/唯一约束保证幂等）。
4. `link`: 将 `submissions.actor_*` 后处理映射到 `students`（可重跑）。
5. `derive`: 计算本场考试的五大指标得分、rating 变化，并更新学生当前画像。

## 4. 幂等保证（强约束）
### 4.1 事务边界
以“考试单位”为事务边界：
- 开启事务
- 写入 `exams` / `exam_files` / `exam_participants` / `submissions` 等
- 写入本场 `exam_student_metrics` / `rating_history`
- 提交

失败则回滚，并在 `ingest_exam_runs` 记录错误信息，便于重跑。

### 4.2 行级去重策略（row_hash）
对提交记录 CSV 的每行构造 `row_hash`（sha256）：
- 先做字段规范化：编码解码、`strip()`、单位转换（KB/ms）、时间解析
- 再对关键字段拼接（或 JSON 序列化）并 hash

在 `submissions` 表中对 `(exam_id, row_hash)` 做唯一约束，实现重复运行不重复插入。

### 4.3 actor 映射策略（可重跑）
- 导入阶段允许 `submissions.student_id` 为空，先保留 `actor_source/actor_external_id/actor_name`。
- 后处理阶段通过 `link-actors` 执行映射更新，冲突记录标记为 `ambiguous`，不强行写入错误关联。
- `link-actors` 必须幂等：重复执行不应重复修改已稳定记录。

## 5. 编码与脏数据处理
### 5.1 编码
提交记录 CSV 的解码建议：
1. `utf-8`
2. `utf-8-sig`
3. `gb18030`

### 5.2 字段清洗
- 字段尾部常见 `\\t`：统一 `strip()`。
- 可能出现 `缺考`、`-`：按缺失值处理（不要强转数值）。
- ICPC 成绩单单元格含换行（`+1\\n61`）：按模式解析。

## 6. 导入与映射后的计算流程（每场考试）
1. 计算该场每个学生的五大指标得分（0-100，必须基于本场相对表现，详见 `doc/五大能力指标与综合能力分设计.md`）。
2. 基于该场排名/成绩计算 rating 变化（初始 800，详见 `doc/五大能力指标与综合能力分设计.md`）。
3. 用时序融合模块更新学生“当前画像”（半衰期/权重可配置）。
4. 若 `link-actors` 产生新的提交-学生关联，需增量刷新对应考试的 `flexibility` 与学生当前画像。
